# Integration console

Part of the [applications](README.md).

## APIs

The Integration console has **no API for its callers** and publishes no OpenAPI document. It is a Blazor UI the Integration operator signs in to (Easy Auth with the `IntegrationConsole.Read` role in Azure, a local operator under Aspire; see [identity-and-access.md](../architecture/identity-and-access.md) and [ADR 0026](../adr/0026-the-integration-console-signs-operators-in-with-easy-auth-and-checks-their-app-role.md)). Its only HTTP endpoints besides the UI's own assets are the `/health` check that Aspire and Container Apps call and, while the Agents are on, the agent API below. Nothing else in the estate calls the console, so there are no other consumers to list.

- **The agent API, `/agent/v1`.** Mapped only while `Agents:Enabled` is on (off by default). It is a read-only view of the use cases for the Integration operations agent, behind a bearer token for the role `IntegrationConsole.Agent.Read` that no operator holds: `GET /agent/v1/trails/{correlationId}` (hops, outcomes, failure codes, Logic App runs and business keys) `GET /agent/v1/runs/{logicApp}/{workflow}/{runId}` (status, and each step's status, duration and error), `GET /agent/v1/failed-runs`, `GET /agent/v1/dead-letter-queues` (count and age of the oldest message per queue and subscription) and `GET /agent/v1/dead-letter-queues/{entity}/messages` (a peek of a queue's oldest messages: reason, description, delivery count, application properties, correlation ID and business keys). It carries no message body and has no write route. Locally the MCP stand-in, `Norvia.Integration.LocalAgentMcp`, is its one caller, as the Agent's identity; in Azure API Management's MCP server is, as API Management's own identity (the token is Entra's, for the app registration `Norvia Integration console agent API`, and the path is outside Easy Auth's gate). It publishes no OpenAPI document of its own: its tools are listed in [integration-operations.tools.json](../../contracts/agent-mcp/integration-operations.tools.json) ([ADR 0040](../adr/0040-agents-read-the-estate-through-api-management-have-no-write-tools-and-their-own-identity.md), [Explain and the agent API](../operations/integration-console.md#explain-and-the-agent-api)).
- **What it calls.** The console reads the estate: it searches Message trails in the Log Analytics workspace and opens Logic App runs through the management API, as its own managed identity and never with the operator's token. The one thing it changes is Service Bus: an operator can resubmit a dead-lettered message through its topic, aimed at the subscription it came from, or discard it ([ADR 0017](../adr/0017-the-integration-console-reads-the-estates-telemetry-and-stores-nothing.md)). Locally it searches the Aspire dashboard's telemetry instead ([ADR 0027](../adr/0027-locally-the-integration-console-searches-the-aspire-dashboards-telemetry.md)). It calls none of the applications' APIs (it reads telemetry and Service Bus, not them), so it is a consumer of none of the other pages.

## Database

The Integration console stores nothing: it reads the estate's telemetry ([ADR 0017](../adr/0017-the-integration-console-reads-the-estates-telemetry-and-stores-nothing.md)), so it has no database.
